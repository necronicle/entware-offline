# entware-offline: отдельный репозиторий офлайн-установщиков Entware

Дата: 2026-10-14. Утверждено Марком в чате (имя репозитория, ссылки во все три
проекта, датированные релизы).

## Зачем

У части провайдеров `bin.entware.net` обрывает загрузку по объёму, и официальный
установщик Entware умирает на шаге скачивания базовых пакетов. Офлайн-установщик
(официальный установщик + его же базовые пакеты + curl, всё сверено по SHA256
официального индекса) решает это для любого проекта на Keenetic: z2k, d2k,
keenetic-doq. Сейчас сборщик, проверка и релиз живут внутри z2k, и людям их
трудно найти. Переносим в отдельный публичный репозиторий `necronicle/entware-offline`.

## Что переезжает из z2k (ветка z2k-staging, коммит 90eb5fdf)

| Было в z2k | Станет | Изменения |
|---|---|---|
| `scripts/entware_offline_build.sh` | `build.sh` | каталог фида в архиве `/opt/var/z2k-offline` → `/opt/var/entware-offline`; комментарии и строка в `bin/install` без упоминания z2k; вызов `sh build.sh <арх> <каталог>` |
| `scripts/entware_offline_smoke.sh` | `smoke.sh` | путь к фиду в проверке «фид удалён»; больше ничего |
| `tests/test_entware_offline_build.sh` | `tests/test_build.sh` | путь к сборщику и к фиду; набор проверок тот же |
| `.github/workflows/entware-offline.yml` | `.github/workflows/build.yml` | триггеры и схема публикации, см. ниже |
| README z2k, раздел «Если Entware не устанавливается» | `README.md` нового репозитория | текст переезжает целиком, добавляются разделы «как собрать самому» и «как проверить» |

Перенос свежей копией одним коммитом с пометкой «перенесено из z2k@90eb5fdf».
История трёх коммитов в z2k не вырезается.

Остаётся в z2k: шим `z2k_opkg` (загрузка пакетов через узел) и README-обход через
зеркало узла. Это рантайм установщика z2k, к офлайн-установщикам не относится.

## Репозиторий

- `necronicle/entware-offline`, публичный, MIT (копия LICENSE z2k), ветка `main`.
- Описание: «Офлайн-установщики Entware для Keenetic: официальный установщик с
  пакетами внутри, сеть при установке не нужна».
- Состав: `build.sh`, `smoke.sh`, `tests/test_build.sh`,
  `.github/workflows/build.yml`, `README.md`, `LICENSE`, `.gitignore` (`out/`),
  `docs/superpowers/specs/` и `docs/superpowers/plans/`.

## Workflow `build.yml`

Триггеры:
- `pull_request` и `push` в `main`: сборка трёх архитектур, установка каждой без
  сети в chroot через qemu, `tests/test_build.sh`, shellcheck на `*.sh`. Публикации нет.
- `schedule` понедельник 03:23 UTC и `workflow_dispatch` на `main`: то же плюс
  публикация, если состав пакетов изменился.

Публикация:
- `ALL.manifest` = три манифеста подряд. Сравнивается с `ALL.manifest` из релиза,
  помеченного Latest. Совпал — выход без релиза.
- Не совпал (или релизов ещё нет) — создаётся релиз с тегом `YYYY-MM-DD` (дата UTC
  запуска), `--latest`, заметки с составом и SHA256, файлы: три архива, три
  манифеста, три diff, `ALL.manifest`. Если тег этой даты уже есть (второй запуск
  в тот же день после смены состава), суффикс `-2`, `-3`.
- Старые релизы не удаляются: откат на прошлую сборку — просто скачать её.

Постоянные ссылки для README всех проектов:
`https://github.com/necronicle/entware-offline/releases/latest/download/<arch>-installer.tar.gz`
где `<arch>` одно из `aarch64`, `mipsel`, `mips`.

Права workflow: `contents: write` только у шага публикации; checkout без
сохранения токена; actions прибиты к SHA, как в z2k.

## README нового репозитория (русский)

1. Что это и зачем, в два абзаца (текущий текст из z2k).
2. Скачать: три ссылки `latest/download`, как узнать архитектуру модели
   (ссылка на официальную инструкцию Keenetic).
3. Установить: положить архив в папку `install` на USB, выбрать накопитель в
   компоненте OPKG; после установки `opkg` смотрит на `bin.entware.net`,
   ключи SSH создаются на роутере.
4. Что внутри и что изменено в официальном установщике: две правки
   (`etc/opkg.conf`, `bin/install`), видны в `*.install.diff` релиза; состав в
   `*.manifest`; чужие «офлайн-архивы» с готовыми ключами dropbear не раздаём и
   почему.
5. Проверить: `sha256sum` против заметок релиза.
6. Собрать самому: `sh build.sh aarch64 out`, проверить `sudo sh smoke.sh
   out/aarch64-installer.tar.gz` (нужен qemu-user-static для чужой архитектуры),
   тест `sh tests/test_build.sh`.
7. Используется проектами z2k, d2k, keenetic-doq (ссылки).

## Правки в проектах

z2k (ветка z2k-staging, один коммит):
- удалить четыре файла из таблицы выше;
- раздел README «Если Entware не устанавливается» сжать до абзаца: причина в одном
  предложении и ссылка на `necronicle/entware-offline`, где инструкция и архивы;
- прогнать `scripts/ci_local.sh` целиком перед пушем.
- На главную ветку попадёт со следующим релизом z2k, который Марк выпускает сам.
  Старый релиз `entware-offline` в z2k до того момента остаётся (на него ссылается
  README главной ветки). В его заметки сверху дописывается строка «переехал в
  necronicle/entware-offline». Удаление старого релиза — после следующего релиза
  z2k, фиксируется в памяти как хвост.

d2k (`main`, один коммит): в разделе про установку Entware абзац «Если Entware
не устанавливается (сервер пакетов обрывает загрузку) — офлайн-установщик:
ссылка».

keenetic-doq (`main`, один коммит): то же, в разделе требований/установки.

Оба клонируются во временный каталог сессии; локальный чекаут d2k не трогается
(стоит на удалённой ветке `classify-core`, которой нет на origin).

## Проверка готовности

1. Локально: `sh tests/test_build.sh` зелёный, shellcheck чистый.
2. Pull request в новом репозитории: CI зелёный на трёх архитектурах (сборка,
   установка без сети, тест).
3. Ручной запуск на `main` создал первый релиз; три ссылки `latest/download`
   отдают 200; SHA256 архивов совпадают с нынешним релизом z2k, если версии
   пакетов не поменялись с 11.10 (иначе сверяются манифесты по версиям).
4. z2k: `ci_local.sh` зелёный, пуш в z2k-staging, CI GitHub зелёный.
5. d2k и keenetic-doq: ссылки в README открываются.

## Вне объёма

- Удаление старого релиза `entware-offline` в z2k (хвост до следующего релиза z2k).
- Любая автоматика «qemu в smoke для всех архитектур локально»: локально
  проверяется своя архитектура, чужие в CI.
- Новые архитектуры или новые пакеты в составе.
